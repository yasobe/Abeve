# Tick (טיק) — developer handoff

Trading journal, risk calculator and reminder app for futures and stock traders. Hebrew, right-to-left, installable on iPhone (home screen web app) and desktop.

- **Live app:** https://yasobe.github.io/Abeve/
- **Repository:** https://github.com/yasobe/Abeve
- **Live branch:** `claude/tick-futures-app` (GitHub Pages serves its `/docs` folder)
- **Backend:** Supabase project `albvjenyvyanzzlmvmqa` (free plan)

---

## 1. What the app does

| Tab | Purpose |
|---|---|
| היום (Today) | Market status (CME Globex / NY session, US holidays), daily loss limit, pre-market routine, next reminder, quarterly roll countdown, month summary |
| שוק (Market) | Watchlist with symbol search (~11.6k US stocks/ETFs + crypto/FX), searchable TradingView chart, index/commodity quotes, US economic calendar |
| מחשבון (Calculator) | Position size for futures (18 contracts) and stocks, R:R, pre-trade checklist |
| יומן (Journal) | Trades (futures + stocks, partial exits, chart screenshots), stats, insights, list/calendar views, CSV export |
| תוכנית (Plan) | Cloud sync login, reminders + push notifications, trading rules, contract rolls, exchange holidays, risk settings, backup/restore |

## 2. Project layout

```
src/app.html                  ← THE source. All UI, CSS and JS live here (single file).
build.py                      ← builds docs/ from src/app.html (splits JS out, adds CSP + PWA head)
docs/                         ← what GitHub Pages serves. index.html + app.js are GENERATED.
  sw.js                       ← service worker (offline cache + push handler). Hand-edited.
  manifest.webmanifest, icons ← PWA install metadata
  symbols.txt                 ← search list, generated by tools/build_symbols.py
  vendor/supabase.js          ← supabase-js 2.117.3 UMD build (vendored, no CDN)
tools/build_symbols.py        ← builds docs/symbols.txt from Nasdaq's public symbol directory
.github/workflows/update-symbols.yml ← monthly job that refreshes symbols.txt
supabase.sql                  ← tables, RLS, storage bucket (initial setup)
supabase-hardening.sql        ← limits, delete_my_account()
supabase-push.sql             ← push tables, vault-backed config, every-minute cron job
supabase/functions/send-reminders/index.ts ← Edge Function that sends push reminders
```

**Never edit `docs/index.html` or `docs/app.js` by hand** — they are overwritten by `build.py`.

## 3. Local development

```bash
python3 build.py                        # src/app.html -> docs/index.html + docs/app.js
python3 -m http.server 8765 -d docs     # open http://localhost:8765/
```

- No npm, no bundler, no framework: plain JS in one IIFE inside `src/app.html`.
- Test on a phone-sized viewport (iPhone 13) and on desktop (≥960px switches to the side-menu layout).
- Supabase sync works from localhost too (the anon/publishable key is public by design).

### Release checklist
1. Edit `src/app.html` (and `docs/sw.js` if needed).
2. **Bump `CACHE` in `docs/sw.js`** (`tick-vNN`) — otherwise installed iPhones keep the old version.
3. `python3 build.py && node --check docs/app.js`
4. Test locally (all 5 tabs, phone + desktop, light + dark).
5. Commit and push to `claude/tick-futures-app` → live in ~1–2 minutes.

### Rules that keep the app safe — please keep them
1. **Escape every value** put into HTML with `esc()`.
2. **Any new field on a trade or in settings must be added to `cleanTrade` / `cleanProfile`**, or it will be silently dropped on load/import/sync. This sanitizing is what blocks malicious backup files (tested).
3. **CSP lives in `build.py`.** New external hosts (APIs, CDNs) must be added there or they will be blocked.
4. **Never put secret keys in the app or the repo.** Only the Supabase *publishable* key and the VAPID *public* key belong in the client.
5. Third-party widgets go in **cross-origin iframes**, never as scripts in our origin.

## 5. Data and sync

- Local: `localStorage["tick_v1"]` (state), IndexedDB `tick` / store `shots` (screenshots).
- Cloud (when signed in), all protected by row-level security (each user sees only their own rows):

| Table / bucket | Contents |
|---|---|
| `public.trades` | one row per trade (`data` jsonb, `deleted` tombstone, `updated_at`) |
| `public.profiles` | settings, rules, reminders, watchlist, routine (`data` jsonb) |
| `storage: shots` | `<user id>/<trade id>.jpg`, JPEG only, ≤3 MB |
| `public.push_subs` | push devices (only Apple/Google/Mozilla/Microsoft push endpoints allowed) |
| `public.push_log` | server-only send history (dedupe) |

Sync is last-write-wins per trade using `updated_at` (client clock). See `syncNow()`.

## 6. Push notifications (how it works)

1. App (from the iPhone home screen, iOS 16.4+) asks permission → `pushManager.subscribe` with `VAPID_PUB` → row in `push_subs`.
2. `pg_cron` job **`tick-reminders`** runs every minute and calls the Edge Function `send-reminders` with an `x-cron-secret` header.
3. The function reads reminders from `profiles`, decides what is due (same NY/holiday rules as the app), sends Web Push, logs to `push_log`.
4. `docs/sw.js` shows the notification (`push` event).

**Secrets** are in **Supabase Vault** (`tick_vapid_public`, `tick_vapid_private`, `tick_cron_secret`), readable only by the service role through `public.tick_push_config()`. If you rotate VAPID keys, update `VAPID_PUB` in `src/app.html` too (all users must re-enable notifications).

**Deploying the function** (Supabase CLI):
```bash
supabase functions deploy send-reminders --project-ref albvjenyvyanzzlmvmqa --no-verify-jwt
```
(`--no-verify-jwt` is required: the function checks the cron secret / user token itself.)

## 8. Known limits / ideas

- CME futures quotes can't be embedded for free (TradingView/CME licensing). Indices are shown in real time instead; stock quotes are ~15 min delayed (marked "D").
- No "forgot password" for non-owners until a custom SMTP (e.g. Resend) is configured in Supabase.
- Symbol list updates monthly (GitHub Action); newly listed stocks can still be added by exact ticker.
- Ideas: broker API integration for live futures prices, Resend SMTP, per-trade tags/filters, weekly email report.
